# 高级编译指南

面向 **真机分发、App Store、CI**。完整步骤（改配置 → 描述文件 → `Make.py build` → IPA）见 **[修改配置与打包.md](修改配置与打包.md)**。

---

## 1. App Store / 企业分发配置
1. 复制并编辑 `build-system/appstore-configuration.json`
2. 复制 `build-system/fake-codesigning`，按 `profiles` 目录示例准备描述文件与 entitlements
3. 在 Apple Developer 创建与 `bundle_id` 匹配的 App ID、描述文件

---

## 2. 生成带签名的 Xcode 工程

```bash
python3 build-system/Make/Make.py \
  --cacheDir="$HOME/telegram-bazel-cache" \
  generateProject \
  --configurationPath=<你的 appstore 配置.json> \
  --codesigningInformationPath=<fake-codesigning 目录>
```

---

## 3. 构建 IPA

使用 **Distribution** 描述文件后：

```bash
python3 build-system/Make/Make.py \
  --cacheDir="$HOME/telegram-bazel-cache" \
  build \
  --configurationPath=<配置.json> \
  --codesigningInformationPath=<签名目录> \
  --buildNumber=100001 \
  --configuration=release_arm64
```

`--buildNumber` 须为递增整数。

---

## 4. prepare-build 脚本链

适用于多 Target（主应用、Share、Widget、Notification 等扩展）：

```bash
cd build-system
sh prepare-build.sh Telegram development   # 或 distribution
```

内部调用：

- `copy-provisioning-profiles-Telegram.sh`
- `prepare-build-variables-Telegram.sh`

生成 `build-input/data` 供 Bazel 消费。

---

## 5. CI 环境变量（verify.sh）

`build-system/verify.sh` 演示了 CI 需导出的变量：

- `API_ID` / `API_HASH`
- `BUNDLE_ID`
- `DEVELOPMENT_TEAM`、签名身份
- 各扩展的 `DEVELOPMENT_PROVISIONING_PROFILE_*` / `DISTRIBUTION_*`
- `BUILD_NUMBER`（必填）

按自有证书与包名修改后，在流水线末尾执行：`source verify.sh && <构建命令>`。

---

## 6. Bazel 与 Xcode 版本

- 严格版本见 `versions.json`
- 临时跳过 Xcode 检查：`python3 build-system/Make/Make.py --overrideXcodeVersion ...`
- 远程缓存：配置 `BAZEL_HTTP_CACHE_URL` 或本地 `BAZEL_CACHE_DIR`（见 `generate-xcode-project.sh`）

---

## 7. 发布检查清单

| 项 | 说明 |
|----|------|
| 服务端 IP | `TeamgramGatewayHost.swift` 指向生产网关 |
| `api_id` | 与后端、其他端一致 |
| 描述文件 | 主应用与全部扩展匹配 |
| 防火墙 | 客户端能访问 10443 / 11443 |
| 品牌 | 应用名、图标符合 Telegram 开源许可要求 |
