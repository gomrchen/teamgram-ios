# 服务端对接配置

iOS 客户端连接 **自建 Teamgram** 时的网络配置说明（非 Telegram 官方数据中心）。

---

## 1. 网关地址（必改）

文件：

```
submodules/TelegramCore/Sources/Network/TeamgramGatewayHost.swift
```

```swift
enum TeamgramGatewayLanHost {
    static let ipv4 = "192.168.1.13"   // ← 改为你的服务器 IP
    static var seedDatacenter1Ips: [String] { [ipv4] }
}
```

| 场景 | 建议 IP |
|------|---------|
| 手机与 Mac 同 WiFi 调试 | 服务器局域网 IP（如 `192.168.1.x`） |
| 公网用户 | 公网 IP 或域名解析结果 |
| 本机模拟器连本机后端 | `127.0.0.1` 仅当模拟器与后端同机时可用 |

修改后须 **重新编译** 客户端。

---

## 2. 端口

| 协议 | 端口 | 后端服务 |
|------|------|----------|
| MTProto TCP | **10443** | `gnetway` |
| MTProto TCP | 5222 | `gnetway`（可选） |
| WebSocket | **11443** | `gnetway` |

逻辑在 `submodules/TelegramCore/Sources/Network/Network.swift` 中写死端口 `10443`，一般无需改客户端端口，只需保证服务端 `teamgram/etc/gnetway.yaml` 已监听且防火墙放行。

---

## 3. 后端检查

```bash
# 服务端
bash teamgram/scripts/start.sh
lsof -i :10443 -i :11443

# 从 Mac 探测
nc -zv <服务器IP> 10443
```

日志：`teamgram/logs/gnetway.log`、`session.log`。

---

## 4. API 凭证

`build-system/*.json` 中：

```json
"api_id": "你的 api_id",
"api_hash": "你的 api_hash"
```

须与 [Telegram 开发者平台](https://my.telegram.org) 申请的一致；与 Android / Desktop 自建端建议统一。

---

## 5. 测试登录

- 企业版测试环境常见验证码：**12345**
- 若握手失败：检查 RSA 密钥是否与后端 `server_pkcs1.key` 匹配（见 `teamgram.io/enterprise/docs/更换授权密钥.md`）
- 若超时：优先排查 IP、端口、VPN、蜂窝网络是否可达私有 IP
